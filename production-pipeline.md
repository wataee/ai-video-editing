# production-pipeline.md — Технический регламент FFmpeg, Remotion и кодирования

> **Назначение документа:** Стандартизация инженерного конвейера обработки видео и звука.  
> Документ регулирует входной аудит файлов, предотвращение деградации качества при пережатии, обработку звука по EBU R128 и финальный экспорт.

---

## 1. Входной аудит исходников (до начала монтажа)

Категорически запрещено приступать к коду или нарезке, не собрав полные метаданные исходников.

### Анализ через `ffprobe`
Перед началом работы Claude запускает проверку входных файлов:

```bash
ffprobe -v error -show_entries stream=index,codec_type,codec_name,width,height,r_frame_rate,avg_frame_rate,pix_fmt,sample_rate,channels,bit_rate -show_entries format=duration,size,bit_rate -of json raw/input.mp4
```

### Чеклист аудита исходных медиа:
1. **Геометрия и ориентация:** Точное разрешение кадра (ширина × высота), ориентация (метатег `rotate` или display matrix для съёмок со смартфонов).
2. **Частота кадров (FPS):**
   - Проверь совпадение `r_frame_rate` и `avg_frame_rate`.
   - Если они различаются — в файле **переменная частота кадров (VFR)**, характерная для смартфонов и записей звонков (Zoom/Telegram).
   - *Действие при VFR:* Перед монтажом конвертируй видео в постоянную частоту кадров (CFR, например 30 или 60 fps) без потерь качества, иначе гарантирован рассинхрон аудио и видео при сборке в Remotion.
3. **Аудиодорожки:** Наличие звука, частота дискретизации (44.1 кГц vs 48 кГц), количество каналов (стерео/моно).
4. **Пиксельный формат и цвет:** `yuv420p`, `yuv422p`, 10-bit HDR или Rec.709. Если исходник HDR, спланируй цветокоррекцию/тонокомпрессию (tone mapping), чтобы ролик не стал блёклым и серым в Rec.709.

## 2. Защита качества от повторного пережатия (Generation Loss)

Каждый проход кодирования алгоритмами с потерями (lossy: H.264, H.265) ухудшает детализацию, размывает текстуру кожи и плодит артефакты компрессии.

### Золотые правила конвейера:
1. **Никаких лишних проходов FFmpeg:** Если финальное видео полностью собрано и отрендерено движком Remotion с нужными параметрами кодека — **не нужно повторно прогонять его через FFmpeg!**
2. **Промежуточные мастера (Intermediate Master):** Если ролик требует постобработки в FFmpeg после Remotion (например, наложение фильтров, тонкая склейка с тяжелыми футажами):
   - Рендери из Remotion промежуточный файл в кодеке без видимых потерь: **Apple ProRes 422 HQ** (контейнер `.mov`) или **H.264 с CRF 10–12 / Preset Slow**.
   - Только финальный шаг конвейера переводит видео в целевой легковесный веб-формат H.264.
3. **Сохранение нативной частоты кадров:** Не меняй частоту кадров без веской причины (например, не переводи 25 fps в 30 fps без ретайминга, иначе появится стробоскопический эффект и дёргание движения).

## 3. Обработка звука: Баланс, чистка и нормализация (EBU R128)

Звук формирует более половины впечатления от видео. Чистая, разборчивая речь важнее фоновой музыки.

### Редакторские требования к аудио:
- **Разборчивость речи:** Голос спикера должен звучать выпукло, плотно и разборчиво на любых динамиках смартфона.
- **Отсутствие артефактов шумоподавления:** Чрезмерное агрессивное шумоподавление превращает голос в «робота» или «звук из-под воды». Лучше оставить лёгкий естественный шум помещения, чем убить тембр голоса.
- **Чистота стыков (Crossfades):** На каждой склейке аудио ставь микрофейд (5–15 мс) во избежание щелчков (clicks/pops).
- **Баланс микса (Ducking):** Фоновая музыка не должна соперничать с голосом по частотам и громкости. Уровень музыки держи на 14–20 дБ тише речевых пиков, применяй автоматический сайдчейн/даккинг.
- **Плавные хвосты:** Звук не должен обрываться мгновенно с последним кадром видео; дай затухание (fade-out) на 0.2–0.5 с.

### Нормализация громкости через FFmpeg `loudnorm`
Целевые стандарты по умолчанию (если в брифе не указано иное):
- **Интегральная громкость (Integrated Loudness, I):** `-14 LUFS` (стандарт YouTube, Reels, TikTok).
- **Истинный пик (True Peak, TP):** `-1.0 dBTP` (защита от клиппинга при перекодировании платформой в AAC/Opus).
- **Диапазон громкости (LRA):** `11 LU` (комфортная компрессия для мобильных устройств).

#### Режим 1: Быстрый однопроходный (Draft / Preview)
```bash
ffmpeg -i input.mp4 -c:v copy -af "loudnorm=I=-14:TP=-1.0:LRA=11" -c:a aac -b:a 192k -ar 48000 output.mp4
```

#### Режим 2: Высокоточный двухпроходный (Final Master)
*Шаг 1: Замер характеристик микса:*
```bash
ffmpeg -i work/mix.wav -af "loudnorm=I=-14:TP=-1.0:LRA=11:print_format=json" -f null - 2> work/loudness_stats.json
```
*Шаг 2: Применение измеренных параметров (значения берутся из JSON первого шага):*
```bash
ffmpeg -i work/mix.wav -af "loudnorm=I=-14:TP=-1.0:LRA=11:measured_I=-18.2:measured_TP=-2.1:measured_LRA=9.5:measured_thresh=-28.8:offset=0.2:linear=true" -c:a pcm_s24le work/audio_normalized.wav
```

## 4. Финальное кодирование видео

### Выбор между CRF и целевым битрейтом
- **CRF (Constant Rate Factor) — Рекомендуемый стандарт:** Обеспечивает постоянный визуальный уровень качества независимо от сложности сцены. Простые статичные кадры не расходуют лишний битрейт, а сложные динамичные сцены не рассыпаются на пиксели.
  - **CRF 18** — официальная рекомендация Remotion и золотой стандарт индустрии для H.264 (визуально неотличим от оригинала).
  - Для супер-высокого качества: `CRF 16`.
- **Заданный битрейт (CBR/VBR 2-pass):** Используется только тогда, когда в ТЗ клиента есть строгое ограничение на размер файла (например, рекламные кабинеты с лимитом до 50 МБ).

### Базовая проверенная команда финального экспорта
```bash
ffmpeg -i work/master.mov \
  -c:v libx264 \
  -preset slow \
  -crf 18 \
  -pix_fmt yuv420p \
  -c:a aac \
  -b:a 192k \
  -ar 48000 \
  -movflags +faststart \
  out/final_video.mp4
```

**Разбор ключевых флагов:**
- `-preset slow`: лучший баланс размера и сжатия без артефактов.
- `-pix_fmt yuv420p`: обязательная совместимость с мобильными браузерами и старыми устройствами (предотвращает чёрный экран).
- `-movflags +faststart`: переносит атом метаданных `moov` в начало файла для мгновенного онлайн-воспроизведения без ожидания полной загрузки.

## 5. Скрипты предварительной подготовки исходников

### Конвертация VFR ➔ CFR (при обнаружении плавающего фреймрейта):
```bash
ffmpeg -i raw/vfr_phone_video.mp4 -vf "fps=30" -c:v libx264 -crf 14 -preset fast -c:a aac -b:a 256k work/cfr_source.mp4
```

### Извлечение чистой аудиодорожки для транскрибации и чистки:
```bash
ffmpeg -i raw/interview.mp4 -vn -c:a pcm_s16le -ar 16000 -ac 1 work/speech_for_whisper.wav
```

### Сборка финального видеоряда и сведённого звука без повторного кодирования видео:
```bash
ffmpeg -i work/remotion_video_only.mp4 -i work/final_soundtrack.wav \
  -c:v copy \
  -c:a aac -b:a 192k -ar 48000 \
  -movflags +faststart \
  out/ready_to_qa.mp4
```
